# 消息管理模块详细设计文档

## 一、概述

### 1.1 文档目的

本文档基于《基础平台需求规格说明书》中消息管理相关需求，结合现有 `auth-center` 项目代码结构，给出消息渠道、消息模板、发送方案、消息日志、选人规则五个子模块的详细设计方案。

### 1.2 现状分析

| 维度 | 现有实现 | 目标 |
|------|---------|------|
| 消息存储 | `user_msg` 表仅支持站内信，`msg_type` 仅区分普通/预警 | 统一消息日志，支持多种消息类型（task/alarm/warning/message/notice/activity） |
| 发送能力 | 无渠道概念，站内信直接入库 | 支持站内信、微信（企微应用消息/企微群机器人/小程序/公众号）、短信（阿里云/腾讯云）、钉钉（应用消息/机器人） |
| 内容管理 | 无模板概念，标题/内容由调用方硬编码 | 消息模板支持变量占位符，同一模板可绑定多渠道 |
| 发送策略 | 无方案概念，SDK 直推 | 发送方案组装渠道+模板+接收人策略，业务系统调用方案编码即可 |
| 接收人 | 调用方显式传入 `targetUsers` | 支持动态传参和规则计算两种接收人策略 |
| 重试机制 | 无 | 自动重试（间隔20秒，最多5次） |
| 编号规则 | 无自动编号 | 渠道编号 `A-MessageCh-000001`，模板编号 `A-MessageTem-000001`，方案编号 `A-MessageSch-000001`，规则编号 `A-Rule-000001` |

### 1.3 设计约束

- **信创兼容**：SQL 与字段设计需适配 DM8 和 MySQL
- **多租户**：所有新表均需 `tenant_id` 字段，实现租户隔离
- **API 兼容**：现有 SDK 的 `POST /api/portal/v1/sdk/msg` 接口保持不变，作为"应用直推"入口
- **高性能**：消息发送为高频操作，核心路径需异步化

## 二、模块架构

### 2.1 整体架构

```
                              ┌─────────────────────────────┐
                              │       业务系统调用方          │
                              └──────┬──────────┬───────────┘
                                     │          │
                        调用方案编码   │          │  应用直推(兼容旧接口)
                                     ▼          ▼
                              ┌──────────────────────────────┐
                              │       SDK / API 入口          │
                              │  /sdk/msg/send (方案调用)     │
                              │  /sdk/msg      (应用直推)     │
                              └──────────┬───────────────────┘
                                         │
                                         ▼
                              ┌──────────────────────────────┐
                              │       发送方案 (Scheme)       │
                              │  模板 + 渠道组合 + 接收人策略  │
                              └──────┬───────────────────────┘
                                     │
                          ┌──────────┼──────────┐
                          ▼          ▼          ▼
                    ┌──────────┐ ┌────────┐ ┌──────────┐
                    │ 消息模板  │ │ 消息渠道│ │ 接收人策略│
                    │ Template  │ │ Channel│ │ Receiver │
                    └────┬─────┘ └───┬────┘ └────┬─────┘
                         │           │           │
                         ▼           ▼           ▼
                    ┌─────────────────────────────────────┐
                    │         消息发送引擎 (Engine)        │
                    │  模板渲染 → 渠道路由 → 发送 → 记日志 │
                    └─────────────┬───────────────────────┘
                                  │
                    ┌─────────────┼─────────────────────┐
                    ▼             ▼             ▼       ▼

              │ 站内信   │ │ 企微/钉钉 │ │  短信  │ │ 消息日志│
              │ (本地DB) │ │ (HTTP)   │ │ (HTTP) │ │ (DB)   │
              └─────────┘ └──────────┘ └────────┘ └─────────┘
```

## 三、数据库设计

### 3.1 消息渠道表 `msg_channel`

```sql
create table if not exists msg_channel
(
    id           char(26)                               not null comment 'ulid'
        primary key,
    channel_no   varchar(30)                            not null comment '渠道编号，如A-MessageCh-000001',
    channel_name varchar(20)                            not null comment '渠道名称',
    channel_type varchar(20)                            not null comment '渠道类型：wechat/sms/dingtalk/site_msg',
    provider     varchar(30)                            not null comment '服务商编码',
    config_json  text                                   null comment '渠道配置参数JSON',
    description  varchar(200) default ''                not null comment '渠道说明',
    forbidden    tinyint      default 0                 not null comment '0-启用，1-禁用',
    tenant_id    varchar(20)                            not null comment '租户id',
    create_user  char(26)     default '0'               not null,
    update_user  char(26)     default '0'               not null,
    create_time  datetime     default CURRENT_TIMESTAMP not null,
    update_time  datetime     default CURRENT_TIMESTAMP not null on update CURRENT_TIMESTAMP,
    delete_time  bigint       default 0                 not null,
    constraint ux_msg_channel_no
        unique (channel_no, delete_time),
    constraint ux_msg_channel_name
        unique (channel_name, tenant_id, delete_time)
) comment '消息渠道';

create index ix_msg_channel_tenant
    on msg_channel (tenant_id, channel_type, forbidden);
```

**渠道类型与服务商枚举值：**

| channel_type | provider | 说明 |
|---|---|---|
| `site_msg` | `none` | 站内信 |
| `wechat` | `wecom_app` | 企业微信应用消息 |
| `wechat` | `wecom_bot` | 企业微信群机器人 |
| `wechat` | `mini_app` | 微信小程序订阅消息 |
| `wechat` | `mp` | 微信公众号 |
| `sms` | `aliyun` | 阿里云短信 |
| `sms` | `tencent` | 腾讯云短信 |
| `dingtalk` | `dingtalk_app` | 钉钉应用消息 |
| `dingtalk` | `dingtalk_bot` | 钉钉群机器人 |

**config_json 结构示例：**

企微应用消息：
```json
{"corpId": "xxx", "agentId": "xxx", "secret": "xxx"}
```

企微群机器人：
```json
{"webhook": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"}
```

阿里云短信：
```json
{"accessKeyId": "xxx", "accessKeySecret": "xxx", "signName": "阿里云短信测试签名"}
```
> 注意：`signName` 为阿里云侧已审核通过的短信签名名称，发送短信时必须传入。
> 阿里云短信使用官方 SDK（`com.aliyun:dysmsapi20170525`）调用，无需自行实现签名。

腾讯云短信：
```json
{"secretId": "xxx", "secretKey": "xxx", "smsSdkAppId": "1400xxxxx", "signName": "腾讯云短信测试签名"}
```
> 注意：`smsSdkAppId` 为腾讯云短信应用的 SdkAppId，在腾讯云短信控制台创建应用后获取。
> `signName` 为腾讯云侧已审核通过的短信签名。
> 腾讯云短信使用官方 SDK（`com.tencentcloudapi:tencentcloud-sdk-java-sms`）调用，SDK 封装了 TC3-HMAC-SHA256 签名机制。

站内信：`null`（无需额外配置）

## 五、核心流程设计

### 5.1 编号生成

所有编号格式统一：`{租户前缀}-{类型前缀}-{6位序号}`

- 租户前缀：从租户 ID 或配置中获取字母部分（如租户ID为 `0` 的默认前缀为 `A`）
- 类型前缀：`MessageCh` / `MessageTem` / `MessageSch` / `Rule`
- 序号：租户内自增，6位补零

**实现方案：** 使用 Redis 的 `INCR` 命令维护各类型序号，key 格式：`portal:msg:seq:{tenantId}:{typePrefix}`

```java
@Service
public class MsgSeqGenerator {
    @Resource
    private StringRedisTemplate stringRedisTemplate;

    public String generate(String tenantId, String typePrefix) {
        String key = "portal:msg:seq:" + tenantId + ":" + typePrefix;
        Long seq = stringRedisTemplate.opsForValue().increment(key);
        String tenantPrefix = resolveTenantPrefix(tenantId);
        return tenantPrefix + "-" + typePrefix + "-" + String.format("%06d", seq);
    }
}
```

### 5.4 重试机制

```
消息发送失败
       │
       ▼
  ┌──────────────────┐
  │ 判断是否可重试    │ ← 网络波动/限流 → 可重试
  │                  │ ← 配置错误/渠道禁用 → 不可重试
  └─────┬─────────────┘
        │ 可重试
        ▼
  ┌──────────────────┐
  │ 写入重试队列      │ ← 使用定时任务(ScheduledExecutor)
  │ retry_count++    │ ← 延迟 retry_interval 秒
  └─────┬─────────────┘
        │
        ▼
  ┌──────────────────┐
  │ retry_count < 5? │ ← 是 → 再次发送
  │                  │ ← 否 → 标记最终失败，记录 fail_reason
  └──────────────────┘
```

**实现方案：** 使用 Spring `@Scheduled` + 数据库轮询，不引入额外 MQ：

```java
@Service
@Slf4j
public class MsgRetryScheduler {
    @Resource
    private MsgLogMapper msgLogMapper;
    @Resource
    private MsgSendEngine msgSendEngine;

    @Scheduled(fixedDelay = 20000) // 每20秒
    public void retry() {
        List<MsgLog> pending = msgLogMapper.selectRetryPending();
        for (MsgLog log : pending) {
            msgSendEngine.retrySend(log);
        }
    }
}
```

### 5.5 选人规则计算

```java
@Service
public class RuleComputeService {
    @Resource
    private SelectRuleConditionMapper conditionMapper;
    @Resource
    private UserService userService;

    /**
     * 根据规则ID计算目标用户列表
     */
    public Set<String> computeTargetUsers(String ruleId) {
        List<SelectRuleCondition> conditions = conditionMapper.selectByRuleId(ruleId);
        Set<String> result = null;
        for (SelectRuleCondition cond : conditions) {
            Set<String> users = resolveCondition(cond);
            if (result == null) {
                result = users;
            } else {
                // 条件间取交集
                result.retainAll(users);
            }
        }
        return result != null ? result : Set.of();
    }

    private Set<String> resolveCondition(SelectRuleCondition cond) {
        return switch (cond.getCondType()) {
            case "org" -> resolveOrgCondition(cond);
            case "role" -> resolveRoleCondition(cond);
            case "user" -> resolveUserCondition(cond);
            default -> Set.of();
        };
    }
}
```

**配置类：**

**发送实现：**

```java
@Component
@Slf4j
public class AliyunSmsSender implements ChannelSender {
    @Override
    public String getChannelType() { return "sms"; }
    @Override
    public String getProvider() { return "aliyun"; }

    @Override
    public MsgSendResult send(MsgSendContext context) {
        AliyunSmsConfig config = JsonUtils.readValue(context.getConfigJson(), AliyunSmsConfig.class);
        try {
            // 创建客户端（建议单例+缓存，避免重复创建）
            com.aliyun.dysmsapi20170525.Client client = createClient(config);
            // 构造请求
            SendSmsRequest request = new SendSmsRequest()
                .setPhoneNumbers(context.getTargetUserPhone())
                .setSignName(config.getSignName())
                .setTemplateCode(context.getThirdTemplateId())
                .setTemplateParam(JsonUtils.toJsonStr(context.getVariables()));
            // 发送
            SendSmsResponse response = client.sendSms(request);
            if ("OK".equals(response.getBody().getCode())) {
                return new MsgSendResult(true, null);
            } else {
                return new MsgSendResult(false, response.getBody().getMessage());
            }
        } catch (Exception e) {
            log.error("阿里云短信发送失败", e);
            return new MsgSendResult(false, e.getMessage());
        }
    }

    private com.aliyun.dysmsapi20170525.Client createClient(AliyunSmsConfig config) throws Exception {
        Config clientConfig = new Config()
            .setAccessKeyId(config.getAccessKeyId())
            .setAccessKeySecret(config.getAccessKeySecret());
        return new com.aliyun.dysmsapi20170525.Client(clientConfig);
    }
}
```

**阿里云 SendSms 接口关键参数说明：**

| 参数 | 必填 | 说明 |

| PhoneNumbers | 是 | 接收手机号，逗号分隔最多1000个 |
| SignName | 是 | 已审核通过的短信签名名称 |
| TemplateCode | 是 | 已审核通过的短信模板Code（对应 thirdTemplateId） |
| TemplateParam | 否 | 模板变量JSON字符串，如 `{"code":"1234"}` |

**注意事项：**
- 建议发送超时设置 ≥ 1秒
- 阿里云短信不支持幂等，需在业务层做好防重
- QPS 限制 5000/秒
- 返回 `Code=OK` 表示提交成功，最终发送状态以回执为准

### 6.4.2 腾讯云短信发送实现

腾讯云短信使用官方 SDK（API 3.0），SDK 封装了 TC3-HMAC-SHA256 签名机制。

**配置类：**

```java
@Data
public class TencentSmsConfig {
    private String secretId;
    private String secretKey;
    /** 腾讯云短信应用 SdkAppId */
    private String smsSdkAppId;
    /** 腾讯云侧已审核通过的短信签名 */
    private String signName;
}
```

**发送实现：**

```java
@Component
@Slf4j
public class TencentSmsSender implements ChannelSender {
    @Override
    public String getChannelType() { return "sms"; }
    @Override
    public String getProvider() { return "tencent"; }

    @Override
    public MsgSendResult send(MsgSendContext context) {
        TencentSmsConfig config = JsonUtils.readValue(context.getConfigJson(), TencentSmsConfig.class);
        try {
            // 创建认证与客户端（建议单例+缓存）
            Credential cred = new Credential(config.getSecretId(), config.getSecretKey());
            HttpProfile httpProfile = new HttpProfile();
            httpProfile.setEndpoint("sms.tencentcloudapi.com");
            ClientProfile clientProfile = new ClientProfile();
            clientProfile.setHttpProfile(httpProfile);
            SmsClient client = new SmsClient(cred, "ap-guangzhou", clientProfile);

            // 构造请求
            SendSmsRequest req = new SendSmsRequest();
            req.setSmsSdkAppId(config.getSmsSdkAppId());
            req.setSignName(config.getSignName());
            req.setTemplateId(context.getThirdTemplateId());
            // 手机号需加 +86 前缀
            req.setPhoneNumberSet(new String[]{"+86" + context.getTargetUserPhone()});
            // 模板参数：腾讯云使用 String 数组，按模板中变量顺序传入
            if (context.getVariables() != null && !context.getVariables().isEmpty()) {
                req.setTemplateParamSet(context.getVariables().values().toArray(new String[0]));
            }

            // 发送
            SendSmsResponse resp = client.SendSms(req);
            SendStatus status = resp.getSendStatusSet()[0];
            if ("Ok".equals(status.getCode())) {
                return new MsgSendResult(true, null);
            } else {
                return new MsgSendResult(false, status.getMessage());
            }
        } catch (Exception e) {
            log.error("腾讯云短信发送失败", e);
            return new MsgSendResult(false, e.getMessage());
        }
    }
}
```

**腾讯云 SendSms 接口关键参数说明：**

| 参数 | 必填 | 说明 |
|------|------|------|
| SmsSdkAppId | 是 | 短信应用 SdkAppId，在腾讯云短信控制台创建应用后获取 |
| SignName | 是 | 已审核通过的短信签名内容 |
| TemplateId | 是 | 已审核通过的模板ID（对应 thirdTemplateId） |
| TemplateParamSet | 否 | 模板参数数组，按模板中变量顺序传入，如 `["1234"]` |
| PhoneNumberSet | 是 | 手机号数组，国内短信需加 `+86` 前缀，如 `["+861390000xxxx"]` |

**注意事项：**
- 腾讯云短信 SDK 使用 TC3-HMAC-SHA256 签名，SDK 已封装，无需自行实现
- 国内手机号需加 `+86` 前缀
- QPS 限制 3000/秒
- `TemplateParamSet` 是有序数组，按模板变量出现的顺序传入（不同于阿里云的 JSON Map）
- 返回 `Code=Ok` 表示提交成功

## 九、关键设计决策

### 9.1 消息发送异步化

**决策：** 消息发送采用线程池异步执行，接口立即返回。

**理由：**
- 外部渠道（企微/钉钉/短信）调用耗时不可控
- 多渠道+多接收人场景下同步发送会导致接口超时
- 便于重试机制实现

**方案：**
```java
@Configuration
public class MsgThreadPoolConfig {
    @Bean("msgSendExecutor")
    public Executor msgSendExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(16);
        executor.setQueueCapacity(500);
        executor.setThreadNamePrefix("msg-send-");
        executor.setRejectedExecutionHandler(new CallerRunsPolicy());
        return executor;
    }
}
```

### 9.2 编号生成方案

**决策：** 使用 Redis INCR 自增序号。

**理由：**
- 编号需租户内唯一且连续
- Redis 原子操作保证并发安全
- 相比数据库序列更轻量

**降级方案：** Redis 不可用时，使用数据库 `SELECT MAX(seq) + 1` 加行锁。

### 9.3 模板变量渲染

**决策：** 使用正则匹配 `{varName}` 模式，从 `variables` Map 中替换。

```java
public class TemplateRenderer {
    private static final Pattern VAR_PATTERN = Pattern.compile("\\{(\\w+)}");

    public static String render(String template, Map<String, String> variables) {
        if (variables == null || variables.isEmpty()) return template;
        Matcher m = VAR_PATTERN.matcher(template);
        StringBuffer sb = new StringBuffer();
        while (m.find()) {
            String varName = m.group(1);
            m.appendReplacement(sb, variables.getOrDefault(varName, "{" + varName + "}"));
        }
        m.appendTail(sb);
        return sb.toString();
    }
}
```

### 9.4 渠道配置参数加密存储

**决策：** `config_json` 中的敏感字段（secret、accessKeySecret等）使用 AES 加密存储。

**理由：**
- 渠道配置含第三方密钥，不能明文入库
- 符合安全合规要求

**实现：** 使用 `hbcy-common` 中已有的加解密工具类，在 Model 层做加解密转换。

### 9.6 短信渠道的第三方模板管理

**决策：** 短信渠道的签名和模板必须在阿里云/腾讯云控制台预先审核通过，平台侧通过 `thirdTemplateId` 字段关联第三方模板。

**理由：**
- 短信受运营商监管，签名和模板必须审核后才可发送
- 阿里云需要传入 `SignName`（签名）+ `TemplateCode`（模板Code）+ `TemplateParam`（模板变量JSON字符串）
- 腾讯云需要传入 `SmsSdkAppId`（应用ID）+ `SignName`（签名）+ `TemplateId`（模板ID）+ `TemplateParamSet`（模板变量有序数组）
- 平台侧的 `msg_content` 仅作预览/备注用途，实际发送内容由第三方模板决定

**实现要点：**
1. 渠道配置中 `signName` 是渠道级参数（同一渠道下所有模板共用同一签名），放在 `msg_channel.config_json` 中
2. `thirdTemplateId` 是模板内容级参数（不同短信模板对应不同的第三方模板），放在 `msg_template_content.third_template_id` 中
3. 发送时引擎从渠道配置取 `signName`，从模板内容取 `thirdTemplateId`，组合调用第三方 API
4. 阿里云推荐使用官方 SDK（`dysmsapi20170525`），腾讯云推荐使用官方 SDK（`tencentcloud-sdk-java-sms`）
5. 腾讯云模板参数使用有序数组 `TemplateParamSet`，需注意变量顺序与模板中变量顺序一致

### 9.7 用户手机号获取

**决策：** 发送短信时，通过用户ID查询 `sys_user.phone` 字段获取手机号。

**理由：**
- 短信渠道需要手机号作为接收地址
- 现有 `sys_user` 表已有 `phone` 字段
- 发送引擎在构建 `MsgSendContext` 时自动填充 `targetUserPhone`

```java
// MsgSendEngine 中
User user = userMapper.selectById(targetUserId);
context.setTargetUserPhone(user.getPhone());
```

**决策：** 选人规则独立实现，不复用现有权限体系中的权限单元用户关系。

**理由：**
- 权限单元用户关系是"用户-组织-权限单元"三维关系，核心做权限控制
- 选人规则是"条件组合→用户集合"的映射，核心做动态选人
- 两者查询模式不同，强行复用会增加复杂度
- 但选人规则的条件解析可复用 `UserService.filterUser4Select` 的底层能力
